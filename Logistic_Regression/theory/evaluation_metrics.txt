EVALUATION METRICS FOR CLASSIFICATION
=====================================

TWO DIFFERENT QUESTIONS
--------------------------------------------------------------------------------
The model outputs a probability. Acting on it needs a threshold. Those are two
separate things, and almost every metric confusion comes from mixing them.

    "Are the PROBABILITIES good?"    ranking and calibration quality.
                                     Threshold-free. AUC, log loss, Brier.

    "Are the DECISIONS good?"        what happens after you pick a cutoff.
                                     Threshold-dependent. Accuracy, precision,
                                     recall, F1.

A model can be excellent at the first and terrible at the second, purely because
0.5 was the wrong cutoff. Knowing which question a metric answers tells you
whether to retrain the model or just move the threshold.

We start with the threshold-dependent family, because that is where the counting
happens.


1. THE CONFUSION MATRIX
--------------------------------------------------------------------------------
Fix a threshold, and every prediction lands in one of four boxes. Churn model,
positive class = "will churn":

                            PREDICTED
                     churn          no churn
      ACTUAL churn   TP             FN
            no       FP             TN

Read the names literally, they are not arbitrary:

    second word = what the model SAID     (positive / negative)
    first word  = whether it was RIGHT    (true / false)

So a False Positive is a positive prediction that was wrong. In plain terms:

    FP = false alarm       we chased a user who was never going to leave
    FN = missed detection  a user churned and we never saw it coming

Everything below is a ratio of these four numbers. Which ratio you care about
depends entirely on which of FP and FN costs you more.


2. ACCURACY, AND WHY IT LIES
--------------------------------------------------------------------------------
    Accuracy = (TP + TN) / (TP + TN + FP + FN)

"Of all predictions, how many were right?" The obvious first metric, and the one
that fails first.

    95% of users do not churn. A model that predicts "no churn" for everybody
    scores 95% accuracy and has learned nothing at all.

That is the whole problem: accuracy lets the majority class carry the score. It
also refuses to say what KIND of mistake you are making — 100 false alarms and
100 missed churners look identical to it, even though they cost wildly different
amounts.

Use it when the classes are roughly balanced AND false positives and false
negatives cost about the same. Otherwise it is at best incomplete.

    Error rate = 1 - Accuracy. Some teams track this instead, to keep attention
    on failures rather than on a comfortable-looking percentage.


3. PRECISION — THE COST OF FALSE ALARMS
--------------------------------------------------------------------------------
Since accuracy hides the type of error, split it. First question: when the model
says positive, how often is it right?

    Precision = TP / (TP + FP)

It looks only at what the model FLAGGED, and ignores everything it passed over.
So precision is the metric that cares about false positives.

    High precision  few false alarms; careful before calling something positive
    Low precision   trigger-happy; flags a lot of things that turn out fine

Use it when a false positive does real damage:

    Spam filtering        an important email lands in the spam folder and the
                          user never sees it
    Push notifications    irrelevant alerts train the user to switch them off
    Content moderation    legitimate posts get removed, and users complain

What precision will not tell you: how many real positives you missed entirely.
A model that flags exactly one user, correctly, has 100% precision while missing
999 churners. That is why it is never quoted alone.

    PRECISION@K, for ranked output. Nobody scrolls to search result 100, so
    measure precision only where users actually look: of the top K results, how
    many were relevant? Precision@K = relevant in top K / K.


4. RECALL — THE COST OF MISSES
--------------------------------------------------------------------------------
The other half. Of all the real positives out there, how many did we catch?

    Recall = TP / (TP + FN)        also called sensitivity, or the true
                                   positive rate

Recall is the metric that cares about false negatives.

Use it when a miss is what hurts:

    Medical screening   a disease goes undetected
    Fraud detection     a fraudulent transaction is allowed through
    Churn prevention    a subscriber leaves before anyone reaches out

And symmetrically, recall alone is gameable in the opposite direction: flag
EVERY email as spam and you catch 100% of spam — perfect recall, and a useless
product, because precision has collapsed.

    Precision and recall are two ways of being wrong. Optimizing one alone
    always destroys the other.


5. THE TRADE-OFF, AND F1
--------------------------------------------------------------------------------
Precision and recall move in opposite directions as you slide the threshold.
Lower it and you flag more users: recall rises, precision falls. Raise it and
the reverse happens. You cannot maximize both.

F1 combines them into one number:

    F1 = 2 × (Precision × Recall) / (Precision + Recall)

It is the HARMONIC mean, not the plain average, and that choice matters:

    precision 0.1, recall 0.9  ->  plain average 0.50
                               ->  F1            0.18

The harmonic mean punishes imbalance. F1 is high only when BOTH are high, so it
cannot be gamed by pushing one to an extreme.

Use F1 when the data is imbalanced, both error types matter, and you need a
single number to compare models.

What F1 ignores: true negatives entirely, and probability quality completely. So
it is the wrong choice when the negative class is the thing you care about, or
when you need trustworthy probabilities rather than decisions.


6. SPECIFICITY
--------------------------------------------------------------------------------
Recall's mirror image on the negative class:

    Specificity = TN / (TN + FP)        the true negative rate

"Of all the actual negatives, how many did we correctly leave alone?" Like
precision it is damaged by false positives, but it measures them against all
true negatives rather than against all flagged items.

It matters most when the negative class is the population you must not disturb —
screening healthy patients, or not blocking legitimate transactions. It is also
half of the ROC curve, which is where we go next.


7. THE THRESHOLD IS A DECISION, NOT A DEFAULT
--------------------------------------------------------------------------------
Everything so far assumed a fixed cutoff. That cutoff is yours to choose, and
0.5 is only what happens when you do not choose. 0.5 assumes a false positive
and a false negative cost the same, which is rarely true.

    Churn: a false positive sends a ₹50 coupon to someone who was staying. A
    false negative loses a ₹3,000/year subscriber. Roughly 60:1, so accept many
    more false alarms — threshold near 0.15.

    Card blocking: now a false positive freezes a real customer's card at a
    checkout counter. False positives got expensive, so the threshold rises.

How to pick one:
  - Assign costs to FP and FN, then pick the threshold minimizing expected cost
  - Or fix the constraint you actually have — "we can only call 500 users a
    week" — and take the top 500 by probability
  - Or read it off the precision-recall curve at your required precision

Changing the threshold does NOT require refitting. It is a business decision
made after training, which is precisely why probabilities are worth more than
labels.


8. ROC AND AUC — GRADING THE RANKING
--------------------------------------------------------------------------------
Since the threshold is adjustable, judging a model at one arbitrary cutoff is
unfair. The ROC curve evaluates it at ALL of them at once.

    Airport scanner analogy. Every bag gets a danger score from 0 to 1. The
    manager has a knob that decides when the alarm sounds.

    Knob low  (0.2)  catch every dangerous item, but the alarm fires for every
                     laptop and hairdryer
    Knob high (0.9)  almost no false alarms, but a well-hidden item slips past

The ROC curve plots what happens at every knob position:

    y-axis  True Positive Rate  = recall        "of the bad bags, how many did
                                                 I catch?"
    x-axis  False Positive Rate = 1 - specificity  "of the safe bags, how many
                                                 did I flag by mistake?"

A perfect model climbs straight to the top-left corner: everything caught,
nothing falsely flagged. A useless one is the diagonal.

AUC is the area under that curve — one number for the whole map:

    AUC = 1.0    perfect separation at every threshold
    AUC = 0.85   good; strong ability to tell the classes apart
    AUC = 0.5    coin flip

The useful interpretation: AUC is the probability that a randomly chosen
positive gets a HIGHER score than a randomly chosen negative. It is purely
about RANKING, so it does not care what the actual probability values are, only
their order.

    That is why AUC and F1 answer different questions. F1 grades today's
    decisions at today's cutoff. AUC grades the model's underlying ability to
    separate. A bad F1 with a good AUC means: keep the model, fix the threshold.


9. PRECISION-RECALL CURVE, AND WHEN ROC LIES
--------------------------------------------------------------------------------
The PR curve sweeps the same threshold but plots precision against recall. Same
idea, different axes — and under heavy imbalance the difference is decisive.

    10,000 transactions, 100 of them fraud (1%). At some threshold the model
    catches 90 frauds and flags 900 transactions in total.

    Recall = 90/100  = 0.90        looks excellent
    FPR    = 810/9900 = 0.082      looks excellent -> ROC curve looks great
    Precision = 90/900 = 0.10      9 out of every 10 alerts are wrong

ROC looks healthy because FPR divides by the 9,900 negatives, and 810 false
alarms is a small slice of a huge denominator. Precision divides by the 900
things you actually flagged, where those same 810 errors dominate.

    Rule: when the positive class is rare and the cost lands on the flagged
    cases (fraud queues, disease screening, moderation), trust PR-AUC. ROC-AUC
    stays optimistic because the negative class is so large.

Note the baselines differ too. A random model scores 0.5 on ROC-AUC, but on
PR-AUC it scores the positive rate — 0.01 here. So a PR-AUC of 0.4 on 1% fraud
is strong, not weak.


10. LOG LOSS AND BRIER — GRADING THE PROBABILITIES
--------------------------------------------------------------------------------
Everything so far measured ordering or decisions. Neither checks whether "0.8"
means anything. For that you need the probability itself scored.

    Log loss = -[ y·log(p) + (1-y)·log(1-p) ]      averaged over all rows

This is the training loss reused as a metric, and it punishes confident errors
brutally:

    truth is 0, model said 0.60   ->  loss 0.92
    truth is 0, model said 0.99   ->  loss 4.61

Five times the penalty for the same wrong answer, held with more conviction. A
model can improve its AUC while its log loss gets worse — the ranking got
better, the probabilities got more overconfident.

    Brier score = mean( (p - y)² )

Same purpose, gentler slope, and it reads as a mean squared error on
probabilities. Lower is better for both; 0 is perfect.

Use these whenever the probability is the product — expected-value calculations,
risk scores, bidding, anything downstream that multiplies by the number.


11. CALIBRATION
--------------------------------------------------------------------------------
Log loss and Brier mix two things: ranking and calibration. Calibration isolates
the second, and it asks a simple question.

    Of all users the model gave a 20% churn probability, did roughly 20% of them
    actually churn?

If yes, the model is calibrated and "20%" is a fact you can act on. If 45% of
them churned, the ordering may still be perfect while every number is a lie.

Check it with a RELIABILITY CURVE: bin predictions (0-10%, 10-20%, ...), and
plot each bin's average predicted probability against its observed rate. The
diagonal is perfect calibration; below it means overconfident, above means
underconfident.

Two common causes of miscalibration:
  - Resampling or class weighting to fix imbalance. It shifts the base rate, so
    predictions come out systematically too high.
  - Strong regularization, which shrinks scores toward the middle.

Fixes, both fitted on a held-out set: Platt scaling (fit a small logistic
regression on the model's scores) or isotonic regression (non-parametric, needs
more data). Plain logistic regression is usually well calibrated out of the box
— it is optimizing log loss directly — which is one of its quiet advantages over
SVMs and boosted trees.


12. MULTICLASS
--------------------------------------------------------------------------------
With K classes the confusion matrix becomes K x K: rows are actual classes,
columns are predicted, and the diagonal is what you got right. Off-diagonal
cells tell you WHICH classes get mistaken for each other, which is usually the
most actionable thing in the whole evaluation.

Precision, recall and F1 are defined per class (that class as positive, the rest
as negative). To get one number, you average — and how you average matters:

    MACRO      unweighted mean over classes. Every class counts equally, so a
               tiny class carries the same weight as a huge one. Use when rare
               classes matter as much as common ones.

    WEIGHTED   mean weighted by class support. Reflects overall performance,
               but a large class can hide failure on a small one.

    MICRO      pool all TP, FP and FN across classes, then compute once. Favours
               large classes. For single-label problems micro-F1 equals
               accuracy.

    Genre classifier where 80% of plays are drama. Macro-F1 exposes that the
    model never gets "romance" right; weighted-F1 barely notices.

Always report which averaging you used. "F1 = 0.82" is meaningless in a
multiclass setting without it.


13. CHOOSING A METRIC
--------------------------------------------------------------------------------
Start from what an error costs, not from what is easy to compute.

    Balanced classes, symmetric costs        Accuracy
    Imbalanced, cost sits on flagged cases   Precision, PR-AUC
    Misses are the expensive error           Recall
    Need one number, both errors matter      F1
    Judging the model, not the cutoff        ROC-AUC
    Probabilities feed a decision or price   Log loss, Brier, calibration
    Ranked output where only the top counts  Precision@K
    Multiclass                               Macro-F1 (or weighted), plus the
                                             K x K confusion matrix

Two habits worth keeping:
  - Report a threshold-free metric AND a threshold-dependent one. The pair tells
    you whether a weak result means a weak model or a bad cutoff.
  - Say which threshold produced the second number. A precision figure without
    its threshold cannot be compared to anything.
