Accuracy :
Accuracy measures how many predictions the model got right overall :  “Out of all predictions, how many were correct?”

Formula : Accuracy = (TP + TN) / (TP + TN + FP + FN)
Accuracy = Correct predictions / Total predictions


When Accuracy Is Useful
Dataset is balanced
Cost of FP and FN is similar
Example: Simple exam pass/fail classification

When Accuracy Is Misleading
Dataset is imbalanced
Example: 95% users do not churn
Model predicts “no churn” for everyone
Accuracy = 95% (but model is useless)


Accuracy
Does not tell what kind of mistakes are made : False Positives or False Negatives
Which type of error is happening more?
Ignores class imbalance

Accuracy tells how many predictions are right, not how the model is wrong.

Error Rate = 1 - Accuracy
Why it matters: 
In high-stakes fields (like aerospace or high-frequency trading), 
teams often focus on "reducing the error rate" rather than "increasing accuracy" 
to keep the focus on the failure points.

Feature,               Accuracy
Best Case,             "Balanced classes, equal costs of error."
Worst Case,            "Rare event detection (fraud, rare disease)."
Sensitivity,           High sensitivity to majority class; ignores the minority class.
Alternative,           "Use F1-Score, Precision, or Recall if classes are imbalanced."
------------------------------------------------------------------------------------------------------------------------------------------------

What is Precision ?:
----------------------------
Precision measures how many of your predicted positives are actually correct.
"When the model says Positive — how often is it right?"

Precision = TP / (TP + FP)
          = Correct Positives/All Predicted Positives
​
Precision only looks at what the model predicted as positive — it completely ignores everything the model predicted as negative.

What Precision Cares About:
-------------------------------------------------------------------
Precision cares about False Positives.

Precision	           What it means
High Precision	    Few false alarms — model is careful before calling something positive
Low Precision	           Many false alarms — model is trigger-happy with positive predictions

When to Use Precision
-------------------------------------------------------------------
Use Precision when False Positives are costly — when wrongly predicting positive causes real harm.
Classic example: An innocent person goes to prison. The model said "guilty" (Positive) — but was wrong. That False Positive has serious consequences.


Real-World Examples
📧 Spam Detection
FP → A legitimate, important email gets marked as spam
User misses a critical email because the model was wrong about a positive
→ False Positives are costly here, so Precision matters

🔔 Recommendation Notifications
FP → User gets a notification for something completely irrelevant
Repeated false alarms → user gets annoyed → turns off notifications
→ False Positives are costly here, so Precision matters


What Precision Does NOT Tell You
Precision alone does not tell you how many actual positives the model missed.
A model can achieve 100% Precision by predicting positive only once — and getting it right. But it may have missed 999 actual positives.
That's why Precision is never used alone — it's always paired with Recall.


Precision@K — For Recommendations & Search
The Context
In systems like Google Search or Netflix, users only look at the top few results. Nobody scrolls to result 100.
The Metric
Precision@K measures how many of the top K results were actually relevant.

Precision@K = Relevant results in top K / K

Why it matters
If the first 3 results are great, the user thinks the model is perfect — even if the 100th result is a False Positive.
The 100th result is irrelevant to the user experience. So you measure Precision only where users actually look — the top K.

Feature                      Precision
Question                     """Is this 'Positive' result actually real?"""
Focus                        Reducing False Alarms.
Weakness                     Completely ignores False Negatives (missed cases).
Best For                     "Spam filters, Content moderation, Criminal sentencing."

-----------------------------------------------------------------------------------------------------------------------------------------------
Recall (Sensitivity / True Positive Rate)

Recall measures how many actual positives the model correctly identified.
“Out of all the real positives, how many did the model catch?”

Formula:
Recall = TP / (TP + FN)
Recall = Caught Positives / All Actual Positives

Objective:
Recall cares about minimizing False Negatives.
High recall means:
Few missed positives
Model rarely says “No” when it should say “Yes”

When to use:
Use Recall when False Negatives are costly.

Medical diagnosis
FN → disease goes undetected
Fraud detection
FN → fraud transaction allowed


Recall alone does not tell:
How many false alarms the model makes. A model can achieve very high or even perfect Recall by simply classifying everything as positive.
exteme example:
Consider a spam filter that aims for 100% Recall of spam emails.
If this filter classifies every single incoming email (both legitimate and spam) as "spam," it will indeed catch all the actual spam emails. Its Recall would be 100%.
However, this filter would be useless because it would also incorrectly flag every legitimate email as spam (a huge number of False Positives). This model would have very low Precision.
-----------------------------------------------------------------------------------------------------------------------------------------------
F1 Score : 

F1 Score measures the balance between Precision and Recall.

“Is the model precise when it claims a positive, and thorough at finding all actual positives?”

Why Do We Need F1 Score?
Precision and Recall often trade off:
Increasing Precision ↓ Recall
Increasing Recall ↓ Precision
F1 Score combines both into one number.

F1 = 2 × (Precision × Recall) / (Precision + Recall)
It is the harmonic mean, not the average.
The "Punishment" Effect: The harmonic mean penalizes extreme values.

F1 is high only if both Precision and Recall are high.
If either is low → F1 drops sharply.

Use F1 when:
Dataset is imbalanced
Both FP and FN matter
You want a single metric to compare models

What F1 Score Ignores
True Negatives (TN)
Probability calibration
So F1 is not ideal when:
Negative class is important

F1 Score tells how well the model balances missing positives and raising false alarms.
Best Case: Fraud detection, Disease screening (where positives are rare but vital).
Worst Case: When the negative class is the focus (e.g., identifying "not spam" emails).
-----------------------------------------------------------------------------------------------------------------------------------------------

Specificity (True Negative Rate)

Specificity measures how well the model correctly identifies negative cases.
“Out of all actual negatives, how many did the model correctly predict as negative?”

Specificity = TN / (TN + FP)
Where:
TN = True Negatives
FP = False Positives

Specificity = Correct Negatives / All Actual Negatives

Focus only on actual negatives.
Specificity cares about False Positives.

High specificity means:
Few false alarms
Model is good at saying “No” when it should

Use Specificity when False Positives are costly.

2. ROC Curve and AUC (The "Threshold" View)
To understand this, you first have to realize that Logistic Regression is actually a "probability machine." It doesn't say "Yes" or "No"; it says "There is a 73% chance this is a Yes."

The "Real-World Example": Airport Security Scanner
Imagine an AI scanner at an airport trying to detect prohibited items (the Positive class).

The scanner gives every bag a "danger score" from 0.0 to 1.0.

0.1: Probably just socks.

0.5: Looks like a dense electronics bundle.

0.9: High certainty of a prohibited item.

1. The Threshold (The "Sensitivity" Knob)
The airport manager has a knob they can turn to decide when to trigger the alarm:

Low Threshold (0.2): The alarm is very sensitive. You’ll catch every single dangerous item (High Recall/True Positive Rate), but you’ll also trigger the alarm for every laptop and hairdryer, annoying everyone (High False Positive Rate).

High Threshold (0.9): The alarm only goes off for "sure bets." You won't annoy many innocent people (Low False Positive Rate), but you might miss a well-hidden dangerous item (Low True Positive Rate).

2. The ROC Curve (The "What-If" Map)
The ROC Curve (Receiver Operating Characteristic) is a map of what happens at every possible position of that knob.

It plots the True Positive Rate (Recall) on the Y-axis.

It plots the False Positive Rate (False Alarms) on the X-axis.

The Goal: You want a curve that climbs straight to the top-left corner (high success, zero false alarms).

3. AUC: Area Under the Curve (The "Quality Score")
If the ROC Curve is the "map," the AUC is the "grade" for how good the scanner is overall.

AUC = 1.0: The perfect scanner. It can perfectly separate dangerous items from socks at any threshold.

AUC = 0.5: A useless scanner. It’s basically flipping a coin. The curve is just a diagonal line.

AUC = 0.85: A very good scanner. It has a high probability of ranking a "dangerous bag" higher than a "safe bag."

Why is this better than F1 Score?
Think of the F1 Score as a "snapshot." It tells you how the scanner is doing today because the knob is currently set to 0.5.

The AUC tells you the potential of the scanner. Even if today's F1 score is bad because the threshold is poorly chosen, a high AUC tells you: "Don't throw the scanner away! The AI is actually great at telling items apart; we just need to find a better threshold (knob setting)."

Key Insight: > * ROC/AUC evaluates the Model's Ability to distinguish between classes.

F1 Score evaluates the Decision's Success at one specific cutoff.

Summary Checklist:
True Positive Rate (TPR): "Out of all the bad bags, how many did I catch?"

False Positive Rate (FPR): "Out of all the safe bags, how many did I accidentally flag?"

AUC: "Regardless of where I set the alarm, how good is this AI at knowing the difference between a bomb and a boot?"
