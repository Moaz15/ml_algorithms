ISOLATION FOREST (IsolationForest) 
=========================================================

0) What problem does Isolation Forest solve?
--------------------------------------------
Isolation Forest is an UNSUPERVISED anomaly detection algorithm.

Goal:
- Find rare / unusual data points (anomalies / outliers)
- Usually without labels for anomalies

Common use-cases:
- Fraud detection (rare suspicious transactions)
- Intrusion detection (odd network events)
- Sensor monitoring (machine failure patterns)
- Data quality (bad records, impossible values)


1) Why anomaly detection is hard (the "needle in a haystack")
-------------------------------------------------------------
Anomalies are difficult because:

A) Rare
- Often < 1% (sometimes < 0.1%) of all data

B) Unknown / changing
- You may not know all anomaly patterns in advance
- New anomaly types appear over time (e.g., new fraud strategy)

C) Baseline difficulty of "old style" methods
Many older methods are distance/density-based, like:
- kNN outlier detection
- LOF (Local Outlier Factor)
- One-Class SVM (not exactly distance-only, but similar spirit)

They try to model "normal" as: dense clusters, then flag far-away points.

Practical issues:
- They can be expensive on large data (many methods compare points to many points)
- High-dimensional data makes distances less meaningful ("curse of dimensionality")


2) Key idea of Isolation Forest (flip the problem)
--------------------------------------------------
Instead of modeling what "normal" looks like, Isolation Forest asks:

"How quickly can I isolate (separate) this point from the rest using random splits?"

Core intuition:
- Normal points live in dense regions -> harder to isolate -> need many splits
- Anomalies are rare and/or in sparse regions -> easy to isolate -> need few splits

The 2 traits it exploits:
- Anomalies are few (low frequency)
- Anomalies have different attribute values (they stand out in feature space)


3) How Isolation Forest builds models (Isolation Trees / iTrees) (Important)
---------------------------------------------------------------
Isolation Forest is an ensemble of randomly built trees called isolation trees.

For each tree:

1) Subsample rows (max_samples)
   - typically a small number like 256, even if you have millions of rows
   reason:
   -Building a tree on all rows is slower. If you build 100–500 trees, it becomes expensive.
   -Enough to isolate anomalies: Isolation Forest doesn’t need perfect boundaries. It needs random partitioning. 
    A small sample (like 256) is usually enough for anomalies to stand out.
   - Each tree sees a different random subset → trees become different → more robust final score.
   - Memory friendly: Works even when dataset is huge.

2) Recursively split the data:
   a) pick a random feature
   reason :
   Creates randomness/diversity: Different trees split on different features, so they partition space differently.
   Avoids expensive search: Normal decision trees try many features to find the best split. Here we intentionally avoid that.
   Prevents over-relying on one feature: Randomness spreads “attention” across features.

   b) pick a random split value between min and max of that feature (in that node)

   Again: no expensive optimization.
    In CART/ID3, you test many thresholds and compute Gini/Entropy to pick the best. That’s slow.
    Random cuts are enough to isolate rare points.
    Anomalies often sit away from dense clusters, so even random cuts tend to separate them quickly.
    Makes trees different: Even with same feature, different random thresholds → different partitions.

3) Stop when:
   - node has 1 sample, OR
   - reached max_depth (often about log2(max_samples))

Why training is fast:
- Splits are RANDOM (no searching best threshold like Gini/entropy trees)

A normal decision tree split does:

try many features × many thresholds
compute impurity for each
pick best
Isolation Forest does:

pick 1 random feature
pick 1 random threshold
split

- Each tree trains on a small subsample

4) Scoring anomalies (path length = "how fast it gets isolated")
----------------------------------------------------------------
For a sample x and a single isolation tree:
- Drop x down the tree until it reaches a leaf
- Count the number of splits taken = path length h(x)

Across many trees:
- Compute average path length: E[h(x)]

Interpretation:
- Smaller E[h(x)] => isolated quickly => more anomalous
- Larger E[h(x)]  => needs many splits => more normal


5) Anomaly score (what’s happening mathematically)
--------------------------------------------------
A common scoring form:

s(x) = 2 ^ ( - E[h(x)] / c(n) )

Where:
- n = max_samples used to build each tree
- c(n) = normalization constant (expected path length in a random tree)

Intuition:
- If E[h(x)] is small -> exponent is less negative -> score closer to 1 -> anomaly
- If E[h(x)] is large -> score smaller -> normal

IMPORTANT (scikit-learn detail):
- In sklearn, `decision_function(X)` returns a score where:
  higher => more NORMAL
  lower  => more ANOMALOUS

And:
- `predict(X)` returns:
  +1 = inlier
  -1 = outlier


6) Why it works (simple practical picture)
------------------------------------------
Example:
- 10,000 normal transactions with amount around $10–$200
- 5 fraud transactions with amount around $10,000

Random splits on "amount":
- Many random thresholds will separate $10,000 quickly from the bulk
- So fraud points get short path length -> high anomaly score


7) Complexity & scalability (why it’s popular)
----------------------------------------------
Key production advantage:
- It scales well because:
  - each tree uses a small subsample (max_samples)
  - splits are random and cheap

Rule of thumb:
- Very good for large tabular datasets where you need a fast baseline anomaly detector.


8) Key hyperparameters (scikit-learn)
-------------------------------------
n_estimators:
- number of trees
- more trees => more stable scores (slower)

max_samples:
- samples per tree (subsample size)
- common default: 256
- smaller => faster, potentially more variance
- larger => more stable, more compute

contamination:
- expected fraction of outliers in data (e.g., 0.01)
- used to set decision threshold for predict()
- if wrong: you will flag too many or too few outliers

max_features:
- fraction/number of features per tree
- can help when you have many irrelevant features

bootstrap:
- whether to sample max_samples with replacement
- sklearn default is usually False for IsolationForest

random_state:
- reproducibility

n_jobs:
- parallelism


9) Data preparation (what you must do in practice)
--------------------------------------------------
Scaling:
- Not always required, but recommended if feature scales are very different
  (otherwise random splits may be dominated by large-scale features).

Categorical features:
- Must be numeric
- Typical approach: one-hot encoding
- High-cardinality categoricals: consider grouping rare categories or using
  frequency encoding (one-hot can explode dimensionality).

Missing values:
- Many sklearn versions do not accept NaNs -> impute first
  (median for numeric, "Unknown" for categorical).

Leakage:
- If you include ID-like or timestamp-like leak features, the model can produce
  misleading anomaly rankings.


10) Choosing contamination (very practical)
-------------------------------------------
contamination controls the cutoff for labeling outliers.

If you know expected anomaly rate:
- set contamination close to that (e.g., fraud rate 0.2% -> 0.002)

If you don’t:
- start with small values (0.01, 0.02)
- adjust based on:
  - how many alerts you can review (top-K)
  - confirmation rate from human review
  - a labeled subset (if you can label some anomalies)

Important:
- Even without perfect contamination, Isolation Forest is useful as a ranking model
  (review top-K most anomalous points).


11) Strengths (when it’s a great choice)
----------------------------------------
- Unsupervised (no labels needed)
- Fast and scalable (subsampling + random splits)
- Strong baseline on tabular anomaly detection
- Produces anomaly ranking (not just a hard yes/no)


12) Weaknesses / failure modes (must know)
------------------------------------------
- High-dimensional sparse data:
  random splits can become less informative (e.g., huge one-hot text-like features)

- If anomalies are not “isolatable” by axis-aligned splits:
  anomalies caused only by a complex interaction may be harder to catch.

- Correlated / redundant features:
  usually not fatal, but can reduce effective diversity and clarity.

- Not naturally explainable:
  you don’t get simple human rules like a small decision tree.


13) Evaluation (because labels often don’t exist)
------------------------------------------------
If you have labels:
- prefer PR-AUC, precision@k, recall@k (often more meaningful than accuracy)

If you don’t:
- manual review of top-K anomalies
- track stability across time windows
- compare against simple baselines (z-score, IQR)
- run sanity checks with known bad patterns (if available)

Production metrics:
- alert volume/day
- % confirmed anomalies
- time-to-detect


14) Comparison with common alternatives (quick)
-----------------------------------------------
Z-score / IQR:
- simple and fast, but mostly univariate (misses multivariate anomalies)

One-Class SVM:
- can work but often slower and more sensitive to scaling and kernel parameters

LOF:
- good for local density anomalies but can be heavier and harder for streaming inference

Isolation Forest:
- fast, scalable, strong general-purpose baseline for tabular anomaly detection


15) Minimal scikit-learn usage (copy-paste)
-------------------------------------------
from sklearn.ensemble import IsolationForest

iso = IsolationForest(
    n_estimators=200,
    max_samples=256,
    contamination=0.01,
    random_state=42,
    n_jobs=-1
)

iso.fit(X_train)

scores = iso.decision_function(X_val)   # higher => more normal
pred   = iso.predict(X_val)             # +1 inlier, -1 outlier

# Review most anomalous first:
# anomalies have LOW decision_function scores
idx = scores.argsort()[:50]
